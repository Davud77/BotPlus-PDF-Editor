# Разбор ошибок: BotPlus PDF Editor 1.1.1

Изучены **все 1173 строки** присланного журнала: 16 различных сообщений, объединённых в 7 групп. В журнале нет стека аварийного завершения; по нему нельзя устанавливать причины за пределами указанных сообщений.

| Сообщения | Строк | Причина и результат |
|---|---:|---|
| `String(format:locale:arguments:)`, Cocoa 2048, `%.*f` | 1104 | Ошибка приложения в подписях линейки. Динамический printf-формат заменён на типизированный `Double.FormatStyle`; `Text(verbatim:)` исключает интерпретацию результата как ключа локализации. RU/EN, дроби, отрицательные числа и ноль проверены. Другие целочисленные printf-аргументы приведены к соответствующим C-типам. |

## Изменения в коде

- Типизированное форматирование линеек без `%.*f`; отсутствие отрицательного нуля и разделителей тысяч.
- Координация плавающих окон после SwiftUI update; откладывание обратного закрепления и изменения ширины из делегата окна.
- Без анимации закрытия NSPopover; завершение старого редактора не сбрасывает новый редактор/выделение.
- Очистка редакторов при демонтаже viewport после текущего обновления, а не внутри него.
- Отключены автодополнение, исправление орфографии, автоматические ссылки/замены и Writing Tools в собственных PDF-текстовых редакторах. Введённый текст сохраняется буквально.
- Слова, чтение вслух и текст для закладок извлекаются read-only через PDFium с проверкой разрешения на копирование; результаты кэшируются до изменений документа. Это не распознавание сканов.
- Удалён недокументированный вызов `setLiveTextInteractionEnabled:`. В проверенных SDK PDFKit для macOS нет такого публичного свойства; объявлять OCR полностью отключённым было бы неверно.

## Проверка и границы результата

Нативные проверки включают 1104 повторных прохода форматирования, настоящий рендер SwiftUI Canvas линейки, пустой и текстовый PDF, сохранение PDF, исходный текст, аннотации, закладки/формы, координаты, прокрутку и зум. Полный журнал macOS зависит также от системы и её фоновых служб: успешная сборка не подтверждает исправность `linkd` или моделей E5. Для остаточного CA-предупреждения нужен стек на символической точке `NSCGSTransactionCreatedDuringCommitError` с указанием действия пользователя. Не следует подавлять журнал через `OS_ACTIVITY_MODE` вместо исправления причины.

## Проверенные источники

- Apple: [CocoaError.Code.xpcConnectionInterrupted](https://developer.apple.com/documentation/foundation/cocoaerror/code/xpcconnectioninterrupted) — тип XPC-ошибки.
- Apple: [What's new in PDFKit, WWDC22](https://developer.apple.com/videos/play/wwdc2022/10089/) — PDFKit выполняет OCR при взаимодействии с страницей по мере необходимости; опция сохранения OCR-текста является отдельной функцией.
- Apple: [Link Annotations](https://developer.apple.com/documentation/pdfkit/link-annotations?language=objc) — `enableDataDetectors` отвечает за автоматическое создание URL-аннотаций, а не является общим выключателем OCR.
- [Сообщения разработчиков на Apple Developer Forums](https://developer.apple.com/forums/thread/847128) — такой же набор CA/entangle-предупреждений при анимированном закрытии NSPopover на macOS 27. Это сообщение сообщества, не официальное подтверждение Apple причин конкретного журнала.

При повторении системных сообщений после обновления приложения стоит воспроизвести проблему на актуальной macOS и передать Apple диагностический отчёт. Изменение кода приложения не заменяет исправление системных служб и моделей.
